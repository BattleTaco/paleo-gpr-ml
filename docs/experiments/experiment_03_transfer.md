## 0. Purpose

Quantify and causally explain whether a GPR anomaly detector trained on void/utility data
transfers to high-permittivity fossil-like targets, and whether physics-grounded synthetic
data + polarity-aware adaptation closes the gap. This is the empirical core of the paper.

Honest scope statement (goes in the paper too): I am characterizing a **domain shift**, not
delivering a deployable fossil finder. Every quantitative claim is about *relative* transfer
behaviour under controlled conditions, anchored by a small real-fossil reality check.

---

## 1. Hypotheses and pre-registered decision rules

Primary metric: **mAP@0.5** (detection). Secondary: **recall @ fixed FPR = 0.1 per image**,
and a **polarity-confusion score** (defined in §4). "CI" = 95% bootstrap CI over the test set
(10,000 resamples), aggregated across >=5 training seeds.

| ID | Claim | Supported if | Refuted if |
|----|-------|--------------|------------|
| **H1a** | The transfer gap exists | mAP(bone->bone ceiling) - mAP(void->bone) >= **0.10** AND its CI excludes 0 | drop < 0.05 or CI includes 0 |
| **H1b** | Polarity is the *cause* | void-trained mAP(anti-bone, void-polarity) - mAP(bone, equal \|contrast\|) >= **0.10**, CI excludes 0 | difference ~0 (gap is not polarity) |
| **H1c** | The gap is closable | best adaptation recovers >= **50%** of the H1a gap, CI of recovery excludes 0 | no condition recovers meaningfully |
| **H1d** | It survives real data | adapted detector scores higher than void-trained baseline on the digitized real-fossil set (per-image, one-sided sign test p<0.1 given small N, reported descriptively too) | adapted <= baseline on real data |

Every outcome, including refutation, is a reportable result. A clean "no" on H1b or H1d
is a genuine scientific finding, not a failure. I will report it as such.

## 2. Conditions (the training x test matrix)

Target domains (all generated by the *same* controlled scene generator, §3):
- **void**, air-filled, eps = 1 (matches my real cavities' physics; low-eps, positive top polarity)
- **bone**, fossil-like, eps in [7, 12] (high-eps, negative top polarity)
- **anti-bone**, low-eps target whose \|reflection coefficient\| is matched to bone but with
  *positive* (void-like) polarity. This is the causal control. (Per-host eps; see §3.)
- **null**, target eps = host eps (no contrast). Negative control: should be ~undetectable.

Conditions:
| # | Train data | Test data | Purpose |
|---|-----------|-----------|---------|
| C0a | synthetic void | synthetic void | source-domain ceiling |
| C0b | synthetic bone | synthetic bone | target-domain ceiling |
| C1 | real infra (void/utility) + synthetic void | synthetic bone | **naive transfer (H1a)** |
| C2 | synthetic void | bone vs anti-bone (held-out) | **polarity control (H1b)** |
| C3a | synthetic bone (physics-grounded) | synthetic bone | adaptation: direct synthetic training (H1c) |
| C3b | synthetic void + **polarity augmentation** (random amplitude sign-flip) | synthetic bone | adaptation: cheap mitigation (H1c) |
| C3c | synthetic void -> bone via **adversarial domain adaptation** (DANN-style) | synthetic bone | adaptation: accepted-method comparison (H1c, stretch) |
| C4 | best of C3 | **real digitized fossil B-scans** | **reality anchor (H1d)** |
| Cbase | physics baseline (polarity-triplet matched filter, non-ML) | all synthetic + real | "why ML over interpretation?" |
| Cnull | synthetic void | null target | sanity: confirms detector needs real contrast |

## 3. Data

### 3.1 Real infrastructure (already in repo)
Public benchmark (utilities/voids/intact, 400 & 200 MHz; cite the *Data in Brief* source,
PMC11847285). Used as the realistic source domain in C1. Splits by original scene id
(`src/data/build_splits.py`), no augmentation leakage.

### 3.2 Controlled synthetic sets (gprMax, on the CUDA box)
The controlled-comparison principle: **hold scene geometry, target geometry, depth distribution,
host medium, and clutter realization constant across target domains; vary ONLY the target
dielectric.** That is what lets me read the result causally.

- Generator: `src/data/generate_gprmax_models.py` (to build), parameters grounded in the forward
  model (`docs/notes/08_*`) and `docs/planning/synthetic_data_plan.md`.
- Dielectrics: host = dry sand (4), wet sand (15-25), clay (5-8), limestone (6). Bone in [7,12].
  Void = 1. Null = host.
- **Anti-bone construction (the control), computed per host eps_h:** choose target eps_a < eps_h
  such that \|r_top\| matches bone's. For eps_h = 4 and bone eps_b = 9: r_bone_top = -0.2, so
  solve (sqrt(4) - sqrt(eps_a))/(sqrt(4) + sqrt(eps_a)) = +0.2 -> eps_a ~ 1.78. Same magnitude,
  opposite sign. Recompute per host so the control is always magnitude-matched.
- Frequencies: 400 MHz and 800 MHz (main); 2 GHz as a cross-frequency robustness check
  (Catanzariti regime).
- Size: per the plan, ~75 scenes/target-type x 4 types + backgrounds, with paired scene ids
  across target types so C2 is a true within-scene comparison. Final counts logged at generation.
- **Fidelity validation (required before use):** reproduce Peredo's bone polarity triplet and a
  Catanzariti-style hyperbola in the synthetic output; report the match. Do not use sims that
  fail this check.

### 3.3 Real-fossil anchor (digitized, H1d)
Small test-only set digitized from B-scan figures in Catanzariti (theropod), Peredo (whale),
Bargiano (fossil-FDTD). Provenance, crops, and permission status logged in `papers/sources.md`.
Treated as a semi-quantitative reality check, never as a training set or a benchmark. Limits
(JPEG figures, no raw traces, tiny N) stated explicitly.

## 4. Metrics (exact definitions)

- **mAP@0.5**, standard detection AP at IoU 0.5. Primary.
- **Recall @ FPR 0.1/image**, recall at the score threshold giving 0.1 false positives per
  image. This is the operationally meaningful number for prospecting (you screen, then dig).
- **Polarity-confusion score**, for the matched bone vs anti-bone pair (C2): the difference in
  detection rate / mean confidence between equal-\|contrast\| targets that differ only in sign.
  Directly measures polarity sensitivity.
- **Fidelity metrics (synthetic vs published physics)**, qualitative + amplitude-profile
  comparison of the synthetic triplet/hyperbola against the papers.
- All detection metrics reported with bootstrap CIs and across >=5 seeds (mean +/- CI).

## 5. Models

To show the *finding* is not an artifact of one architecture (a standard reviewer worry), run
the core conditions on **two detector families**:
1. **YOLOv8** (already validated in repo, `notebooks/04_object_detection.ipynb`), one-stage.
2. **Faster R-CNN or RT-DETR**, a second family (two-stage / transformer) for robustness.

If both show the gap (H1a) and the polarity cause (H1b), the conclusion is architecture-agnostic.
Adaptation methods (C3) implemented on the primary architecture; report the second as a
robustness check.

---

## 6. Statistical analysis plan

- >= 5 random seeds per training condition; report mean and 95% bootstrap CI of the metric.
- Differences between conditions tested via bootstrap CI of the difference (excludes 0 = supported).
- H1d uses a one-sided sign test across the small real set, plus per-image descriptive results
  (I will not over-test a tiny sample).
- No metric or threshold is changed after seeing results without a logged, dated amendment.
- Effect sizes reported alongside significance; I avoid "SOTA" language given small effective N.

## 7. Threats to validity -> where handled (the defense map)

| Reviewer objection | Where the design answers it |
|---|---|
| "Synthetic-only, says nothing about reality" | C4 real anchor (H1d) + scope statement framing claims as domain-shift, not field performance |
| "Polarity inversion is just textbook physics" | I say so; novelty is the *measured ML consequence* + the C2 causal control |
| "Gap is just 'synthetic looks different', not polarity" | C2 isolates sign at matched \|contrast\|; null control (Cnull) and anti-bone rule out magnitude/appearance |
| "Why ML over physics-based interpretation?" | Cbase physics baseline; ML must match/beat it while automating |
| "It's a YOLO quirk" | Two architecture families (§5) |
| "Synthetic data isn't realistic" | §3.2 fidelity validation against published forward models before use |
| "Cherry-picked results / moving goalposts" | This pre-registration + logged amendments |
| "Data leakage inflates numbers" | Split by original scene id; paired scene ids for C2 |
| "Infra detection isn't novel" | I agree and cite the public dataset; novelty is the transfer characterization |
| "Underpowered" | >=5 seeds, bootstrap CIs, effect sizes, honest small-N statement for H1d |
